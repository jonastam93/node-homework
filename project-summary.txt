# Project Summary

Project: Todo List Application

Deployed Application:
https://node-homework-jonastam93.onrender.com

## Application Overview

This project is a Todo List application built with a Node.js and Express backend, PostgreSQL database using Prisma ORM, and REST APIs.

Users can register, log in, create and manage tasks, search and filter tasks, view task analytics, create multiple tasks at once, and log in using Google OAuth.

## Extra Features

### 1. Google OAuth

Users can log in using their Google account.

API:

POST /api/users/googleLogon

Request body:

{
"authorizationCode": "authorization-code-from-google"
}

Query parameters:

None

The endpoint authenticates the Google user, creates the user record if needed, sets the JWT session cookie, and returns the user's name, email, and csrfToken.

### 2. Task Pagination and Filtering

The task list supports pagination and case-insensitive title searching.

API:

GET /api/tasks

Query parameters:

* page - page number; defaults to 1
* limit - number of tasks per page; defaults to 10 and has a maximum of 100
* find - searches task titles case-insensitively

Example:

GET /api/tasks?page=1&limit=10&find=home

The response includes the tasks and pagination information.

### 3. Task Analytics

The application provides task and user analytics using Prisma aggregation queries.

Analytics include:

* Completed versus incomplete task statistics
* Recent tasks
* Seven-day task progress
* User task counts
* Incomplete tasks for users

### 4. Bulk Task Creation

Multiple tasks can be created with a single API request.

API:

POST /api/tasks/bulk

Request body:

{
"tasks": [
{
"title": "Finish homework",
"isCompleted": false,
"priority": "high"
},
{
"title": "Go grocery shopping",
"isCompleted": false,
"priority": "medium"
}
]
}

Query parameters:

None

The endpoint validates each task and creates the requested tasks for the authenticated user.

## TASK APIs

### Create Task

POST /api/tasks

Creates a task for the authenticated user.

Request body:

{
"title": "Finish homework",
"isCompleted": false,
"priority": "medium"
}

Query parameters:

None

Returns the created task.

### List Tasks

GET /api/tasks

Returns tasks belonging to the authenticated user.

Query parameters:

* page - page number; default 1
* limit - number of results; default 10, maximum 100
* find - case-insensitive search of task titles

Example:

GET /api/tasks?page=1&limit=10&find=home

Response includes:

* tasks
* pagination

### Get One Task

GET /api/tasks/:id

Returns one task belonging to the authenticated user.

Path parameter:

* id - task ID

Request body:

None

Query parameters:

None

Path parameter:

None

None

## ANALYTICS APIs

### User Analytics

GET /api/analytics/users/:id

Returns analytics for a specific user.

Path parameter:

* id - user ID

Request body:

None

Query parameters:

None

Response includes:

* taskStats - task counts grouped by completion status.
* recentTasks - the user's 10 most recently created tasks, including task details and the associated user's name.
* weeklyProgress - daily task counts for tasks created during the previous seven days, grouped by calendar day.

### Users With Statistics

GET /api/analytics/users

Returns users with task statistics.

Query parameters:

* page - page number; defaults to 1
* limit - number of users per page; defaults to 10 and has a maximum of 100

Example:

GET /api/analytics/users?page=1&limit=10

Response includes:

* users
* pagination

Each user includes task count information and up to five incomplete tasks.

### Task Search

GET /api/analytics/tasks/search

Searches tasks using PostgreSQL raw SQL and ILIKE.

Query parameters:

* q - search text; required and must contain at least 2 characters
* limit - maximum number of results; defaults to 20 and has a maximum of 100

Example:

GET /api/analytics/tasks/search?q=home&limit=20

The search checks both task titles and user names.

Results are ranked so that:

1. Exact title matches appear first
2. Titles starting with the search term appear next
3. Partial matches follow

The search results use a flat response structure. The associated user's name is returned as `user_name` rather than as a nested user object.

Example result:

{
"id": 1,
"title": "Finish homework",
"user_id": 3,
"user_name": "Example User"
}

The overall response includes:

* results
* query
* count

## DATABASE AND DEPLOYMENT

The application uses PostgreSQL with Prisma ORM.

The production PostgreSQL database is hosted on Neon.

The backend application is deployed to Render.

Prisma database migrations are deployed during the Render build process using:

npx prisma migrate deploy
